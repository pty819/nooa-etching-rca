# 文档反思、自审与已知缺口

## 自审方法

本章由同一作者在初稿后按反证方式复核，不称为独立第三方评审。先问“哪些段落可能把愿望写成事实”，再回查当前源码、测试和历史产物；随后严格构建、检查SVG与链接，最后实际浏览公开站点。程序检查和人工判断分别记录，不用一个总分掩盖缺口。

| 维度 | 本次检查方式 | 判断标准 |
|---|---|---|
| 完整性 | 需求、系统、agent、算法、数据、接口、恢复和验收逐项追踪 | 读者能理解从输入到交接，而不只看到功能清单 |
| 事实性 | 对照模块、配置、方法与实际失败边界 | 不把规划、历史实现和当前能力混写 |
| 可复现性 | 锁定依赖、无API文档构建、明确研究平台与数据生成命令 | 新clone不依赖作者私有目录 |
| 图表 | Mermaid真实构建为SVG，检查语法、尺寸、图文一致 | 图能解释边界与状态，不只是装饰 |
| 科学诚实 | 历史案例与隐藏真值后验对照 | 命中异常不等于识别全部根因，错误数值不抹去 |
| 公开性 | Git跟踪范围、key字面值及私有路径检查 | 不把已有会话、凭据或生成数据推上公网 |

## 复核中主动纠正的内容

1. **业务时段范围**：历史90片案例目标为35/25/30，公开发现为30/20/25；新版默认360片为每时段120片，train/dev公开目标每时段90片，不能混用这些计数。
2. **模拟与生产**：厂商材料提供变量分离启发，不提供本模型的已标定系数；没有IEDF、完整CFD或厂商数字孪生。
3. **报告粒度**：当前有中文报告和证据，不保证每个内部计算单元自动形成完整的传感器旧值/新值修订报告。
4. **历史边界缺口与修复**：旧版仅限制科学worker且读取默认放行；审核后外层CodeAct和科学代码均改为无凭据新进程与默认拒绝规则，不能用旧文档边界代表当前实现。
5. **审查效果**：Predict只审给定证据，Reflexion只读且可能返回未满意候选；都不等于独立算法重算或根因认证。
6. **历史问题**：旧RCA报告仍有压力std口径不一致；没有用新门禁验收结果追溯证明旧报告全正确。
7. **发布内容**：公开生成器就公开了构造逻辑，严格盲评需另行隔离；Pages是静态文档，不是带模型的服务。

8. **真正执行浏览器搜索**：首次构建和部署都绿色，但Sphinx 9.1生成的language_data.js引用未定义的ChineseStemmer；同时未安装jieba时中文词不会正常进入索引。通过Sphinx公开的搜索语言注册接口匹配英文词干构造器，保留中文分词，加入jieba与领域词典；增加执行生成JS和检查中文索引的Node回归，再实测“背氦”返回相关页面。
9. **资源检查本身也要审查**：SVG由object的data属性引用，不能只查img的src；同时区分引用中的有效SVG和旧的增量缓存，避免漏检或重复计数。

10. **按新clone复核启动说明**：服务的provider列表读取进程环境，启动命令必须显式加载.env；同时注明Mermaid CLI所需Node版本。根据实际Actions迁移提示固定Ubuntu24.04，避免runner镜像两天后自动迁移导致构建环境漂移。

## 本次公式流程补齐与自审

新增[专家公式比较](formula-research.md)将原始提取、版本、固定验证、模型公平比较、最佳重算和交接放在宿主程序侧。反例检查区分了mean(a*b)与mean(a)*mean(b)，验证20%窗口、失败/排除、失效选择及产物改写；实际NOOA工具链使用脚本响应验收，不声称新一轮独立大模型发现。前端显示规范状态，最终正文由宿主追加公式与分数。

进一步修正了门禁的任务范围：旧实现依据会话历史研究要求后续任务交接，会阻塞无关画图。当前仅本轮启用公式比较时要求交接，只读与新轮普通任务不会触发；真实worker与原生CodeAct画图回归覆盖这一情况。

自审仍保留以下边界：任意代码不具备形式化语义证明；dev反复选择不能称作独立测试；自定义模型尚不能直接加入可信套件；一般研究中的每次内部改算完整中文差异报告仍未强制。不得把新流程的保证扩展到所有自由探索。

## 动态数据升级的反证复核

审阅确认并修复五类问题：原生skills目录绑定失效、正文失败掩盖已保存结果、可选参考表导出不一致、旧异步响应覆盖新会话、任意提取程序可跨对象窥见开发分布。新增回归在真实worker/原生CodeAct边界验证，不以静态猜测代替已复现故障。进一步核对版本继承、分支授权、父/主集回退、恢复、表格/图片/文本实际算子及训练fold拟合。详见[动态数据](dynamic-datasets.md)与[特征隔离](feature-isolation.md)。

真实GLM在既有公开刻蚀数据上完成90→10→4→10→90的划分/读取/回退，并保存源码和计数。首次证据把版本号填入样本ID，被程序拒绝；模型随后修正。首次请求推理约五分多钟，后续独立模型审查达到本次600秒时限；不能宣称该轮端到端审查成功。工具说明补清output字段、脚本变量注入、样本ID与版本号、发布键，并把审查问题单改为只检查任务实际涉及的内容。修订提示不等于已经证明延迟问题消失。后续只读展示在38.5秒内读取已有CSV并交付，状态not_required/delivered，保留上一轮超时说明；没有重算或改称审查通过。Vue页面实际完成嵌套版本选择、血缘展示及返回主集。

发布复核还用反例复现了同名目录资产冲突：旧分支只比较单个文件，目录中的不同内容可能被静默选取。现在文件与目录均比较完整内容指纹，不一致时要求明确物化；新增目录冲突回归先失败、修复后通过。

逐对象执行增加进程启动开销；内容哈希提高审计能力但不是无限数据规模性能保证。自由探索的计算仍不自动受正式公式协议重算，文本中的每个数字也尚无逐句独立重算。实际外部拉数与知识图谱明确延期；不能用测试provider冒充接入成功。

## 已知缺口与优先级

| 优先级 | 缺口 | 合格的后续验收 |
|---|---|---|
| 高 | 更严格的逐次改算中文报告契约 | 强制sensor/feature/step、旧值/新值、原因、撤回项与证据版本，并验证实际UI交付 |
| 高 | 任意研究变换与报告正文数字仍可能错误 | 冻结脚本、独立重算关键统计、逐句数值/单位追踪与反例集 |
| 高 | 真实多场景RCA效果未知 | 隔离提示作者的盲场景、漏检/误报、第二机制识别率和成本对照 |
| 中 | Linux/macOS执行后端需逐平台验收 | Runtime checks运行同等文件/取消/恢复测试；Landlock与命名空间后端均不可用时拒绝执行 |
| 中 | 单mission预算而非部署级预算 | 多会话同时运行的总准入、费用预估与公平性验证 |
| 中 | 源码引用仍会随语义变更漂移 | 扩展可执行需求契约，不只验证文件存在和配置值 |
| 后续 | MCP手册、跨案例记忆和视觉审图 | 指定知识来源、范围控制、真实图像输入与增益对照后再声明 |

## 总体判断

这份文档适合接手开发、评审当前设计和复现工程流程；它有明确的数据、接口、状态、失败与验证边界，而非只介绍成功路径。它不是生产设备规格书、已确认部件根因报告或独立性能论文。最需要继续加强的是科学计算与人话正文之间的逐项可追溯性，以及独立多场景评测，而不是再增加装饰性功能名称。
